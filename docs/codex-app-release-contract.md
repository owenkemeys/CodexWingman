# Codex app release contract

GitHub Releases is the primary source of public installable builds. A committed release identity contains the exact executable version and one to five short user-facing changes or contents. The app's About surface reads that identity, and CI rejects a mismatch between it, the executable version, and the `vX.Y.Z` tag. A public release is created only after the tagged commit passes tests, packaging, archive validation, and platform smoke checks; upload the versioned asset and its SHA-256 before the release becomes the stable update target. Keep internal folder and executable names stable across updates so installed shortcuts do not drift.

Every Codex app should consume a **versioned common release kit** rather than copy updater code. The kit owns the GitHub latest-release parser, stable/prerelease policy, exact asset naming and digest checks, ZIP traversal defense, installed-package manifest verification, transactional same-volume replacement, rollback, and result reporting. App adapters provide the repository, platform asset pattern, installed version, user-facing About content, shutdown/relaunch hooks, and persistent-state locations. Language-specific adapters may call a common external installer, but they must use the same manifest and test vectors. Pin kit versions in each app and automate dependency update proposals when a kit release lands; the passing app build takes the new pin. Publishing a kit fix alone must not silently mutate installed apps. CI tests the pinned kit and builds each app. Wingman consumes the exact `CodexApp.ReleaseKit` `0.1.0-preview.2` NuGet package, packed into the repository's ignored `.packages` feed before restore; the package supplies discovery, download, archive verification, package verification, and the parameterized Windows updater script. A separate .NET consumer test also compiles against that package and receives the script. The `releasekit-vVERSION` tag workflow now prepares a versioned NuGet asset and checksum from public main. No independent kit tag or second real Codex app consumer has been published yet, so the cross-app path remains open.

On startup, check the latest **complete stable** release in the background with a short timeout. A failed network check is quiet. `Check for Updates` performs the same check on demand and explains a failure. A newer version prompt includes the short changes and offers `Update now` or `Later`; declining changes nothing. Never auto-install from a check alone. A release without the expected platform asset and GitHub SHA-256 digest is not installable. A test channel must select prereleases explicitly and show that identity in About.

After acceptance, download to a temporary folder, limit size, verify the GitHub asset digest, reject archive traversal and links, verify every file against the embedded package manifest and version, then start a separate updater outside the running app directory. The updater prepares a sibling staging directory and checks it again before requesting app exit. After a graceful exit, it renames the old package to a rollback sibling, swaps the new package into the stable path, starts the app, and restores the old package if that launch fails. Settings and user data stay outside the package. User-added Helper folders are carried forward without overwriting bundled folders; changed bundled folders remain in the rollback. A package checksum, source test, or successful process start is not proof of rendered acceptance.

For Windows releases, validate the real installer engine and architecture, including a disposable preflight under Windows PowerShell 5.1 when `powershell.exe` is the consumer. Exercise first install, update, repeated update, rollback, a missing optional setting, locked files, and the normal shortcut. Record package, installed, and live states distinctly. Retain the prior working version until the updated app's real launch and UI have been observed.

EventEditor's current About version, tagged GitHub builds, and startup release reminder inform this contract. Its current `Go to Releases` button is a download route, not a self-installing updater. Wingman's checked-in GitHub workflow, About identity, release discovery, and update transaction are the first consumer; they are not a public release or a Windows acceptance result by themselves.
